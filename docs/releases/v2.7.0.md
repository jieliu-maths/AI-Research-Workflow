# 2.7.0 — AI4Math-first public release

Release preparation date: 2026-10-30.

This release packages a reusable mathematical research workflow around explicit
proof obligations, independent review, scoped failures, and owner-approved
changes. It adds public bilingual entry points and a separate experimental
AI4S scaffold without changing the mathematical claim-state vocabulary.

## Included

- English/Chinese README, usage instructions, and reusable role prompts.
- A primary-source comparison of 13 representative systems, including direct
  mathematical workflow/memory comparators QED and MathResearch Ledger.
- MIT licensing, including a notice retained with installed workflow assets.
- Evidence-bundle inspection and a source-theorem applicability audit template.
- Offline finite-arithmetic and synthetic held-out evaluation examples.
- Experimental AI4S fresh-workspace initialization with an independent scientific
  protocol, claim ledger, and frozen experiment plan.
- Source-publication checks and macOS/Linux Python 3.10/3.12 CI configuration.

## Local validation

- 30 regression tests passed on macOS / Python 3.12.
- An actual 2.6.2 installation upgraded to 2.7.0 through preview/apply and then
  passed installed-project validation; the checked canonical mathematical files
  remained byte-for-byte unchanged.
- Both offline examples and the tamper/path/profile refusal checks passed.
- 38 relative Markdown links resolved during preparation.
- Common source-publication leak checks and Git whitespace checks passed.

These checks establish software behavior within their stated scope. They do not
establish mathematical correctness or a productivity advantage. Remote CI results
must be read from GitHub Actions after publication; configuring a matrix is not
proof that every remote job has run.

## Limits

No hosted models, automatic prover/experiment adapters, command replay, or
mathematical truth checker are included. Evidence inspection checks metadata and
file contents. AI4S has no migration, managed upgrade, graph validator, dashboard,
or report generator. A future effectiveness benchmark remains a proposal.

The public initial commit is a clean snapshot. Earlier local development history
is retained locally and excluded from public history to avoid publishing prior
machine-specific examples. Only the public branch and release tag should be
pushed; do not use a mirror or all-branches push for this first publication.
