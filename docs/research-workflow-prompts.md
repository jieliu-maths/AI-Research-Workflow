# 工作流提示词（3.1：单窗口研究）

默认直接在当前窗口开展研究，无需创建或重命名角色聊天。下面的提示词
分别用于安装、恢复研究和关键审查；不需要每次完整复制。

## A — 安装或升级

```text
请使用经过核验的独立工作流库为当前项目初始化、迁移或升级。
工作流库：<WORKFLOW_LIBRARY>

已有可用路径时直接验证；需要定位时，从 Codex 项目列表寻找唯一合格的
独立工作流库。要求 .research-workflow-library.json 的 kind 为
standalone-proof-ledger-research-workflow-library，library_id 为
ai-research-workflow-kernel；"<WORKFLOW_LIBRARY>/workflow" identify 与
"<WORKFLOW_LIBRARY>/workflow" self-check 均通过，且库内没有
.research-workflow.json。旧 source_hint` 只能作为备用候选，仍须相同核验。
没有唯一候选时询问路径，不猜测。

先预览相应的 init / migrate / upgrade 命令，核对目标与冲突后，在本次
授权范围内加 --apply 执行。保留项目数学状态、已提交证据、既有研究轮次
和项目专用限制。不创建角色聊天，不登记三窗口，不配置编排等待。
修改过的旧协议应作为冲突处理，不得覆盖其中的数学限制。
新项目保持空 S0；旧项目的语义映射另作待审批提案。
运行 researchctl validate，核查 summary 和 dashboard；报告默认只需
Markdown，LaTeX/PDF 按需要导出。汇报修改、保留内容、冲突与验证结果。
```

## B — 新项目确定目标

```text
研究问题：<填写>
已知文献、假设与约束：<填写；未知则明确未知>

按 WORKFLOW.md，在当前窗口调研原始文献、可行性、准确目标、主要困难和
机制不同的候选路线。引用准确的定理、页码及适用假设，给出最便宜的判别
检查。向我提交准确目标、主要路线、假设和拟授权的探索范围。审批前可以
做便宜的可行性与否证检查，不激活主要路线或启动其构造。
批准后就在当前窗口继续，无需另建角色任务。
```

## D — 在批准范围内连续研究

```text
按单窗口工作流推进当前数学问题。先运行 researchctl validate，阅读
STATE.md 的短状态、当前 brief 和相关证明账本、假设及记号；长历史按需读。
在已批准的目标、主要路线、假设与探索范围内连续推导、计算、修补和检索，
无需逐步重新请示。改变主要机制、定理范围、假设或正式结论时请求审批。

每轮只需 brief.md、work.md、manifest.json，不要复制整个模板目录。
长推导之前做最便宜的候选检查：认可拓扑、算子/伴随/边界、一阶变分尺度、
既有推导根的完整商、量词和盲方向、截断与尾项、精确失败范围。
局部候选和失败保留在 work.md；提交证据时才建立 Txxx.json 并冻结哈希，
brief 可以兼任 dispatch，work 可以兼任最终 summary，不重复抄写记录。

关键恒等式、核心估计、声称补上证明缺口或正式结论升级触发独立审查。
先冻结不泄露候选证明的题目与约定，在独立上下文或由人工先保存独立推导，
再披露候选作比较。用 review.json 绑定题目、独立推导、候选及评语。
自查不能算独立审查，未能审查则结论待定，可继续不依赖该结论的授权探索。
实质修补需要针对新候选重新审查。

收尾在 work.md 写目标、精确结果或最小排除范围、决定性论证、证明影响、
剩余缺口与下一问题，并用同样的数学语言向我汇报。没有正式变更就不建
状态提案；有则另建提案和 state-transition.json，明确证据与独立审查，
待我批准后才修改正式状态、命题地位、全局记号或获授权的论文内容。

同一路线连续两轮无新增信息、三轮无经独立审查的决定性支持，或出现重复障碍、循环论证和
结构性失败时，暂停新构造，针对障碍重新检索原始文献并独立评估，提交
路线复盘；复盘后的继续或路线改变由我决定。不要自动越过授权范围开新轮。
```

## C — 关键独立审查

```text
请独立审查以下数学命题。第一阶段只阅读题目、假设、约定与允许输入，
不得阅读候选证明或此前研究对话；先保存自己的推导/否证检查并冻结。
第二阶段再阅读候选证明，逐项比较符号、量词、一致尺度、边界项、依赖及
精确结论范围，披露共享推导根与未解决问题。若已看过证明，明确标为自查，
不能伪称独立。结论为拒绝、不确定或暂经受住攻击，均不自动证明命题。
不改正式数学状态，不自行创建其他聊天。
```

## Mathematical feedback / 数学反馈

Follow docs/research-feedback.md. 核对原目标的量词、范围、拓扑和来源假设；
不要证明更容易的替代命题。可执行检查使用冻结 evaluator，只有在已有授权
范围内才执行 --run；保留失败、超时与检查范围。升级计算时先记信息目标、
预算和停止条件。关键证据按 claim/revision 冻结，用 claim_records 与
critical_reviews 关联；proof 不必与 work/summary 同一文件。修改依赖触发
相关版本复核，不自动改变正式命题地位。每轮说明新增信息，两轮 none 提前
复盘。先用同模型、同推理强度、同预算和冻结真实任务比较流程，匿名评审
正确性、命题含义、表述、引用、复现性与人机时间；示例不是科研效果实验。
